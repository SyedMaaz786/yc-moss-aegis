## About your project

Aegis is a runtime trust layer for AI agents, demonstrated on a fictional bank support
assistant. It checks user input, retrieves policy context through Moss, verifies source
integrity against a versioned hash manifest, and inspects generated output before
releasing it. A live attack lab lets judges try prompt injection, obfuscated attacks,
PII requests, poisoned context, invented policy amounts, and a request-scoped retrieval
outage. Every decision exposes sources, stage timings, and an exportable receipt.

Aegis measures usefulness as well as safety: benign evaluation cases require actual
released answers with trusted sources and passing grounding checks. The recorded public
32-case regression run achieved 20/20 adversarial input blocks, 12/12 benign successes,
zero benign input false positives, and 545 ms p95 total latency on the development
machine. Judges can rerun the suite live. The suite is not an independent security
benchmark, and the threat model openly documents the limits of heuristic checks.

The Evidence page also publishes a same-suite Groq/Gemini comparison, including a
failed Gemini request, and a controlled failover receipt using a real Gemini answer.
Backup generation shares every release gate, and receipts show which model was used.

## How did you use Moss in your retrieval layer?

Moss powers semantic threat retrieval, policy retrieval, answer-to-source re-retrieval,
and session trace search. Aegis uses Moss's native custom sessions with 384-dimensional
vectors generated by a bundled quantized MiniLM encoder. Document and query vectors use
the same versioned model. The warm query path runs locally, without a vector database
or a model CDN download.

Moss selects the candidates. Because hybrid ranking scores are not probabilities,
Aegis calibrates only the returned candidates against their normalized vectors before
applying safety thresholds. The UI separately exposes encoder time, native Moss search
time, and full pipeline time. Local pattern matches can stop known attacks before any
model call. Moss retrieval remains central to legitimate answers and output verification.

This path was implemented after observing HTTP 401 from the default model artifact CDN.
The supported custom-embedding interface let the application keep real Moss semantic
retrieval while removing that runtime dependency.
